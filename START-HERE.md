# Подготовка к защите Inception: начни отсюда

Цель: сдать обязательную часть, понимая каждую строку проекта. Bonus — после сдачи.

Нужно 7 дней по 2–3 часа. Каждый день заканчивается проверкой: пока она не пройдена,
дальше не идём.

## Можно ли гарантировать сдачу?

Полной гарантии нет: всё решает живой проверяющий, а таблица на Intra может отличаться
от нашей копии. Но каждый пункт этой копии проверен на работающем стеке, а проверки в плане
повторяют то, что будет на защите. Если все они пройдены честно и без подсказок, ты готов к
любому пункту таблицы.

## Что где лежит

```
START-HERE.md              этот файл: план и прогресс
Inception/                 сам проект (его содержимое сдаётся на Intra)
materials-inception/
  lessons/                 ГЛАВНОЕ: уроки 0–8, идут по порядку
  my-work/
    answers.md             только вопросы (60), ответы пишешь сюда сам
    labs.md                отчёты по практике пишешь здесь
  answer-key.md            эталонные ответы: открывать только после блока вопросов
  defense/
    runbook.md             защита по шагам таблицы, смена порта, каверзные вопросы
    commands.md            шпаргалка команд
  sources/                 Subject и таблица оценки (PDF)
tests/                     автоматическая проверка запрещённых конструкций
```

## Как проходить урок

В каждом уроке три части, в этом порядке:

1. **Прочитай.** Всё нужное уже в уроке, ничего искать не надо.
2. **Сделай руками.** Вводи команды сам, не копируй блоками. Результат запиши в
   [`my-work/labs.md`](materials-inception/my-work/labs.md).
3. **Ответь.** В [`my-work/answers.md`](materials-inception/my-work/answers.md) только вопросы.
   Закрой урок и код и напиши ответы прямо в этот файл, после символа `>`. Всё для них есть в уроке,
   готовые ответы лежат в `answer-key.md`.

**Работай в VM:** открой там репозиторий в VS Code и запусти Claude Code. Копировать ответы и отчёты в
чат не нужно: когда напишешь фразу из таблицы, я прочитаю файл, а лабу ещё и проверю командами на этой же
VM. Новая сессия не помнит прошлую, но правила проверки читает из `CLAUDE.md`, а твою работу из `my-work/`.
На другой компьютер работа переносится через `git push` и `git pull`.

**Проверка мной.** Напиши одну из этих фраз:

| Фраза | Что произойдёт |
|---|---|
| «проверь лабу 3» | проверю отчёт и задам вопросы по нему |
| «проверь блок C» | оценю ответы строго, 0–100% за вопрос; порог 90% |
| «объясни Q24» | объясню, но ответ за тебя не напишу |
| «сломай мне проект» | внесу неисправность, чинить будешь по логам |
| «проведи защиту» | вопросы по одному, без подсказок, в конце разбор |

Не вставляй в отчёты настоящие пароли: `my-work/` попадает в git.

- [ ] После настоящего `sudo reboot` комментарий и правка страницы на месте.
- [ ] Все блоки вопросов ≥ 90%.
- [ ] Проект написан заново по уроку 8.
- [ ] Каверзные вопросы (runbook §14): ответ на каждый за 30 секунд.
