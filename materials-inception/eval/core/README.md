# eval/core — самопроверка по обязательной части

Четыре документа. Порядок не случайный: теория → руки → чистый лист.
Всё рассчитано на работу **без ИИ** — ответы и ожидаемый вывод лежат рядом.

| Файл | Что это | Когда |
|---|---|---|
| `01-theory-questions.md` | 60 вопросов с местом для ответа | когда думаешь, что понял |
| `02-theory-answers.md` | эталонные ответы + критерии оценки | **только после** того, как ответил на всё |
| `03-practical-checklist.md` | 40 проверок на живом стеке, с ожидаемым выводом | когда стек собран |
| `04-rewrite-from-memory.md` | написать проект с нуля по памяти | финальный экзамен |

---

## Как этим пользоваться честно

Главная ловушка самопроверки — узнавание вместо воспроизведения. Прочитал ответ,
подумал «ну да, логично» и записал себе плюс. Через неделю на защите этого нет.

Правила, которые это ломают:

1. **Пиши ответ, а не думай его.** Мысль не проверяется, текст проверяется.
2. **Не открывай файл с ответами, пока не ответил на весь блок.** Не по одному
   вопросу — блоком.
3. **Не подглядывай в код проекта во время теории.** Теория проверяет голову.
4. **Ставь балл строго.** Критерий на каждый вопрос — в файле ответов.
   «Примерно то же самое, только своими словами» — это не 100%, если пропущено
   *почему*.
5. **Не переписывай свой ответ после подглядывания.** Веди отдельную строку
   «что упустил» — по ней потом учить.

---

## Оценка

Каждый вопрос — 0–100%, по критерию рядом с эталонным ответом:

| балл | значение |
|---|---|
| 0% | не ответил или ответил неверно |
| 25% | назвал термин, не объяснил |
| 50% | объяснил *что*, не объяснил *почему* |
| 75% | что и почему, но упущено следствие или деталь из критерия |
| 100% | что, почему, следствие — коротко и точно |

**Порог 90%** — среднее по всем вопросам блока. Ниже — доучить тему по ссылкам в
конце блока и пройти блок заново, не раньше чем через день (иначе проверяешь
кратковременную память, а не понимание).

Заведи файл `my-score.md` рядом:

```
дата | блок | средний % | что упустил
-----+------+-----------+-------------
```

Вторая колонка через неделю важнее первой.

---

## Что значит «готов к защите»

- `01` ≥ 90% — с первого прохода, без подглядывания
- `03` — все проверки зелёные, и по каждой можешь сказать, что она доказывает
- `04` — проект собран с нуля по памяти и запустился

Формально хватает первого. Реально защиту проваливают на `04`: код написан
когда-то и забыт.
