Six containers, one kernel.

A hand-built WordPress infrastructure. No ready-made application images — every service is installed into a bare Debian base, kept to one process, and wired together over a private bridge network.

This page is the bonus static site. Plain HTML, CSS and a little JavaScript — no PHP.

The stack

How a request flows

  1. 1
    Browser → NGINX :443

    TLS 1.2/1.3 terminates here. The only port published to the host.

  2. 2
    NGINX decides

    Static file? Served straight off the volume. .php? Forwarded over FastCGI.

  3. 3
    NGINX → PHP-FPM :9000

    Resolved as wordpress:9000 by Docker's embedded DNS at 127.0.0.11.

  4. 4
    PHP → Redis

    Object cache hit? Skip the database entirely.

  5. 5
    PHP → MariaDB :3306

    On a miss. Unreachable from the host — network isolation, not just a password.

Rules the build follows

  • No latest. Every base image and tool is pinned, so a rebuild is reproducible.
  • No ready-made app images. Debian 12 in, packages installed by hand.
  • PID 1 is the real daemon. No tail -f, no sleep infinity — every entrypoint ends in exec, so the daemon receives SIGTERM.
  • Passwords are files, not env vars. Docker secrets under /run/secrets; docker inspect reveals nothing.
  • Named volumes, not bind mounts. Backed by /home/akuzmin/data via the local driver.
  • One process, one container. No web server inside the WordPress container.
